# cc-rsg 運用指示

- 既存コードから仕様書、保守資料、引き継ぎ資料、納品向け文書を生成または再生成する依頼では、`$cc-rsg` を使う。
- 実装修正、コードレビュー、要約、質問回答、既存文書の軽微な編集だけの依頼では、`$cc-rsg` を使わない。
- 実装やレビューと仕様書生成が混在する依頼では、仕様書生成部分だけに `$cc-rsg` を使う。文書化対象が確定するまで `.cc-rsg/` を新規作成または更新しない。
- `$cc-rsg` を使う場合は、対象範囲、主読者、粒度、出力言語を先に確定し、`.cc-rsg/goal.json` を正本にする。
- 書き込み前に既存の `.cc-rsg/goal.json`、`.cc-rsg/state.json`、`.cc-rsg/questions.json`、`drafts/`、`final/` を確認し、再開、巻き戻し、リセット、新規実行のどれかを確定する。推測で削除または上書きしない。
- コードで確認した事実、推論、未確定事項、回答不能事項を混ぜない。
- 仕様本文の機能、データ、依存、運用、制約に関する主張は、実コードまたは設定への `[REF: path:Lstart-Lend]` で裏付ける。裏付けできない主張は未確定扱いにする。
- 「存在しない」「呼び出し元がない」「Xだけが使う」という不存在・排他主張は、確認した探索範囲を明示する。範囲を示せない場合は未確認扱いにする。
- 調査で解けない疑問は `.cc-rsg/questions.json` に記録し、ユーザー回答で更新する。永続的に回答不能なものは最終成果物の未確定事項に残す。
- 作業は `$cc-rsg` の Phase 0〜6 に従う。偵察、計画、章ドラフト、検証、対話精緻化を飛ばして完成文書だけを作らない。
- 検証では、インベントリ網羅、章品質、参照、Question Bank、必須成果物を確認し、各項目の pass/fail、根拠、失敗時の戻り先を記録する。不合格なら該当フェーズへ戻す。
- 大規模コードベース、または章ごとに独立調査できる場合だけサブエージェントを使う。各サブエージェントは担当章の成果物をファイルに保存し、返答は要約と未解決疑問に絞る。
- Phase 3 で章単位のサブエージェント調査を行う場合は、Codex custom agent `chapter-investigator` を使う。`context_optimization_mode: "B"` の場合は `chapter-investigator-mode-b` を使う。
- サブエージェントの要約だけを根拠にしない。担当ファイルを読み、参照、未確定表示、未解決疑問の `.cc-rsg/questions.json` 反映を確認してから統合する。
- Mermaid は構造表現だけに使う。色、`fill`、`classDef`、装飾目的の `style` は使わない。
- 最終成果物は `.cc-rsg/final/` に置き、未確定事項と検証結果を短く示す。
